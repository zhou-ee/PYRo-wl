# 新旧 IMU 数学数据流的 ARM 机器码检验

2026-10-06。结论：在有限、有效 IMU 输入和正常协方差条件下，未发现核心数学
公式、矩阵维度或所测门控分支的迁移错误。当前浮点优化配置会产生实际舍入差异，
所以“数学公式一致”不等于“每个 float32 结果逐位一致”。边界处理也并非完全相同。

## 方法

除静态反汇编外，将新旧算法链接到同一个 ARM ELF，在 Unicorn 2.1.4 的
Cortex-M7 模型中执行其 Thumb/VFP 机器码。启用 FPU，使用默认 FPSCR；
没有用 Python 公式代替算法、CMSIS 或数学库，所有矩阵和三角运算执行实际 ARM
机器码。Python 仅生成输入、读取内存和比对结果。

使用当前 STM32 编译数据库的工具链、目标、宏和包含目录：
GCC 15.3.1，`cortex-m7 / fpv5-d16 / hard float`。新旧实现共用同一组编译后的
CMSIS 内核和 newlib 数学库。检查三种配置：

- O0：当前项目 `-O0 -funsafe-math-optimizations`。
- O3：`-O3 -funsafe-math-optimizations`。
- O3-strict：仅在审阅构建中关闭 unsafe math、浮点融合与严格别名优化；
  `-O3 -fno-unsafe-math-optimizations -ffp-contract=off -fno-strict-aliasing`。
  未修改正式固件编译选项。

在每个 CMSIS 乘法、转置、加减和求逆的入口读取维度和输入，在返回位置读取
输出和状态码。额外比较四元数、零偏、欧拉角、状态、P、NIS、接受校正时的 K、
增益比例及累计航向；比较收敛、稳定、错误计数和拒绝标志。

每配置 1,027 次更新：normal 512 次、fading 512 次、reject/recover/adaptive
各一次。fading 使用交替周期、lambda=0.9996、周期性加速度脉冲。
后三项显式注入相同的先前门控状态以覆盖拒绝、错误计数超过 50 时恢复及自适应
增益分支。自适应探针用相同首样本的 NIS 设置阈值，使比例约为 0.5555556。
独立场景还恢复旧模型被 Observe 回调覆盖的全局初始 P，避免场景间历史污染。

## 数据流核对

| 阶段 | 从汇编调用和操作数核对的数学逻辑 | 结果 |
| --- | --- | --- |
| 角速度去零偏、陀螺积分 | `omega=gyro-bias`，构造 Fgyro，`x_raw=Fgyro*x`，6×6 乘 6×1 | 一致 |
| 四元数归一化 | 同一魔数 0x5f375a86、同一轮平方根倒数近似，缩放前四个分量 | 一致 |
| 状态雅可比 | 从归一化前的 qw/qx/qy/qz 构造 8 个零偏耦合项，符号和位置相同 | 一致 |
| 预测协方差 | XY 零偏方差除以 lambda 并限制到 10000，`P-=(F*P_faded)*Fᵀ+Q_d` | 一致 |
| 观测模型 | 用归一化后的预测四元数计算 H 和重力方向 h(x)，`y=z-h(x)` | 一致 |
| 残差协方差 | `S=(H*P-)*Hᵀ+R`，3×3 | 一致 |
| NIS | 求逆后先算 `v=S⁻¹*y`，再算 `yᵀ*v`，1×1 | 一致 |
| 卡尔曼增益 | `K=(P-*Hᵀ)*S⁻¹`，6×3 | 一致 |
| 门控和增益调整 | 阈值 0.5/1.0/0.1 倍、稳定错误计数、超过 50 恢复、自适应比例和零偏行缩放 | 所测分支一致 |
| 状态校正 | `dx=K*y`，收敛时限制 XY 零偏增量，`dx[3]=0`，`x_new=x-+dx` | 一致 |
| 校正协方差 | SIMPLIFIED 路径 `P_new=P--(K*H)*P-` | 一致 |
| 姿态发布 | 同一欧拉角公式、度转换和航向跨圈规则 | 正常范围内一致 |

每个完整接受校正的样本核对 19 个对应矩阵调用；拒绝样本核对前 12 个。
每配置共核对 16,342 个对应调用。三种配置的运算种类、维度、顺序及所测门控
决定均无差异。严格配置中，操作数和输出也全部逐字节相同。

有两个结构差异已明确处理，并非遗漏检查：

- 旧实现通过 CMSIS 做 `y=z-h(x)` 和 y 的向量转置；新实现逐分量相减并以行
  视图读取 y。通过下一次 NIS 乘法的完整 y 输入核对其结果。
- 新实现在门控前计算 K，旧实现在门控通过后计算 K。拒绝时，新实现多执行两次
  增益乘法，但没有提交状态/协方差校正。拒绝时旧 K 可能是历史值，新 K 是本次
  候选值，因此拒绝样本的 K 诊断不作为相同字段要求；后续状态数学不依赖该旧 K。

## 实际数值结果

| 配置 | normal | fading | reject / recover / adaptive |
| --- | --- | --- | --- |
| O0 + unsafe | 512 次逐位一致 | 512 次出现舍入差异 | 均逐位一致 |
| O3 + unsafe | 512 次逐位一致 | 512 次出现舍入差异 | reject 的 NIS、recover 的部分输出出现微小差异；adaptive 一致 |
| O3-strict | 512 次逐位一致 | 512 次逐位一致 | 均逐位一致 |

上述三个配置的门控标志和错误计数逐样本相同；fading 均拒绝 452 次。
这不是对任意阈值附近输入都做出相同决定的证明。

fading 场景的最大绝对差：

| 配置 | 四元数 | 欧拉角 / 度 | P 元素 | NIS |
| --- | ---: | ---: | ---: | ---: |
| O0 + unsafe | 5.9604645e-8 | 1.9073486e-6 | 0.00390625 | 4.2632564e-14 |
| O3 + unsafe | 1.1920929e-7 | 1.1444092e-5 | 0.0068359375 | 1.1368684e-13 |
| O3-strict | 0 | 0 | 0 | 0 |

这些差值描述本次样本，不代表误差上界或长期稳定性保证。

## 首次差异的指令来源

在 O0 fading 首样本中，x 轴原始加速度是 6，dt≈0.0009，lpf≈0.01。
两边数学表达式相同，但 unsafe math 对新首样本表达式做了提取公因子的变换。
省略加载/存储后，实际算术指令如下：

```text
旧：
vmul.f32   t0, a_history, lpf
vmul.f32   t1, a_raw, dt
vadd.f32   numerator, t0, t1
vadd.f32   denominator, dt, lpf
vdiv.f32   a_filtered, numerator, denominator

新首样本（a_history 和 a_raw 是同一个局部值）：
vadd.f32   t0, lpf, dt
vmul.f32   numerator, t0, a_raw
vadd.f32   denominator, dt, lpf
vdiv.f32   a_filtered, numerator, denominator
```

旧结果为 5.999999523162842，新结果为 6.000000476837158。
归一化后，旧 z[0]=0.5215219259262085；NIS 使用的旧 y[0]=0.521929144859314，
新 y[0]=0.5219292044639587。之前的 F/P/H/S/求逆矩阵调用输入输出仍相同，
第一次矩阵数据差异出现在 `S⁻¹*y` 的 y 操作数。随后差异传播到 NIS、K 和校正结果。

实数关系 `(a*lpf+a*dt)/(dt+lpf) = a*(lpf+dt)/(dt+lpf)` 成立，
但浮点乘加和除法之间的舍入位置发生变化。O3 还允许融合/重排；关闭这些优化后
本次全部机器码回放逐位一致，支持“所发现差异来自浮点求值过程”的判断，
而不是证明所有可能差异都只有这一个来源。

## 一致性的适用范围

下列行为确实与旧模型不同，不能概括为全输入等价：

- 新实现检查无效加速度、零模长和非法参数，必要时只做预测或返回错误。
- 新实现对 acos/asin 输入加限幅；旧实现直接调用函数。
- 新核心在预测后也施加方差下限；旧模型的下限在整个更新末尾施加。
  本次合法协方差的对应预测值不触发这项差异。
- 新 init 将自适应增益比例初始化为 1，旧全局对象首次为 0；正常首次接受校正
  会为旧比例赋值。合成门控探针显式设置相同历史比例，比较分支自身的逻辑。

本次是有限样本的机器码数据流验证和汇编审阅，不是全程序形式化证明；
模拟器结果也不能用于判断物理 STM32 的执行周期、缓存行为或实际 FPSCR 设置。

## 复现与证据

```powershell
python -m pip install --target build/imu-assembly-audit/python unicorn==2.1.4 pyelftools==0.33
python tests/forward_kf/check_imu_arm_math.py cmake-build-debug-stm32/compile_commands.json build/imu-assembly-audit
```

脚本编译 test-only harness、两种算法及 CMSIS 内核，输出 ARM ELF、
`arm-math-results.json`、每配置/场景的首步矩阵数据流 JSON。
结构或门控判断出现差异时退出失败，O3-strict 出现逐位差异时也退出失败。
unsafe 配置的数值差异记录在报告中，不隐藏或当作完全一致。
完整静态反汇编及首样本低通的 verbose assembly 位于同一个 build 目录。
